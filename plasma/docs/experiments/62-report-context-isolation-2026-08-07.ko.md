# 새 보고서의 이전 대화 문맥 격리

## 확인하려는 문제

계획형·장문 보고서는 일반 대화와 분리된 제공자 세션에서 작성된다. 현재 구현은
새 보고서 세션을 미션의 최신 일반 대화 세션에서 포크한다. 따라서 사용자가 이전
보고서를 대화에서 검토한 뒤 새 보고서를 만들면, 검색 결과에서 이전 보고서를
제외하더라도 그 검토 대화가 새 보고서의 계획에 남을 수 있다.

이 실험은 새 보고서의 최초 계획 세션만 완전히 새로 시작했을 때 문맥 오염과
보고서 품질이 어떻게 달라지는지 확인했다. 검색 경계, 보고서 장부, 명시적 보고서
수정·이어쓰기, 장문 최종 작성 단계는 바꾸지 않았다.

## 실험 방법

같은 시점의 개발 미션 데이터베이스를 두 복제본으로 나누고, 실제 Plasma CLI의
계획형 보고서 경로를 사용했다. 원본 개발 데이터에는 쓰지 않았다.

- 현재 포크군: 최신 일반 대화 세션에서 보고서 전용 세션을 포크했다.
- 새 세션군: 기존 세션 초기화 이벤트 계약으로 최신 일반 대화 세션을 비운 뒤,
  최초 보고서 계획을 새 제공자 세션에서 시작했다.

두 군은 같은 미션, 제목, 방향 지시, 모델, 추론 강도, 작성 지침, MCP 도구와
자료를 사용했다. 모델은 `gpt-5.6-sol`, 추론 강도는 `xhigh`, 작성 지침은
`narrative-contract`로 고정했다. 계획을 만든 뒤의 본문 작성은 각 군의 계획
세션을 그대로 이어 갔다.

대상 미션에는 여러 차례 생성한 Helm 보고서와, 가장 최근 보고서를 검토한 일반
대화가 있었다. 직전 대화는 Kubernetes가 Helm 차트나 release 개념을 이해하지
않으며, release 이력도 Kubernetes 입장에서는 일반 Secret이라는 관점을 강조했다.

원시 데이터베이스, 세션 식별자, 생성 문서와 판독 자료는 저장소 밖의 실험
아카이브에 보관한다. 이 문서에는 공개 가능한 방법과 결론만 남긴다.

## 실행 무결성

두 실행 모두 계획과 본문 생성을 완료했고, 원장 계보는 의도대로 갈렸다.

| 비교군 | 최초 보고서 문맥 | 포크 원본 | 보고서 크기 | 실행 시간 |
| --- | --- | --- | ---: | ---: |
| 현재 포크군 | 최신 일반 대화의 포크 | 있음 | 24,197 bytes | 약 10분 |
| 새 세션군 | 빈 문맥에서 시작 | 없음 | 19,573 bytes | 약 18분 |

새 세션군도 같은 MCP 자료를 읽어 계획과 본문을 완성했다. 실행 시간 차이는 한 쌍의
비교에서 발생한 값이므로 품질 또는 비용 우위로 해석하지 않는다.

## 관찰 결과

차이는 계획 단계에서 먼저 나타났다. 현재 포크군은 직전 대화의 관점을 계획의
`must_keep` 항목으로 올리고, 첫 절에서 Kubernetes가 Helm을 이해하지 않는다는
설명과 release Secret을 핵심 경계로 다시 강조했다. 최종 보고서의 도입부도 직전
대화의 문장과 구성을 가깝게 재사용했다.

새 세션군의 계획에는 이 항목이 없었다. 같은 자료를 읽었지만 차트와 release의
구분, values 병합, 렌더링과 검증, 설치, revision 상태 전이, 단계별 진단 순서로
주제를 다시 구성했다. 최종 보고서는 현재 포크군보다 약 19% 짧았고, 직전 대화의
표현을 서두의 중심축으로 삼지 않았다.

두 보고서 모두 사실 설명과 링크를 유지했고, 새 세션군에서 자료 접근 손실은
관찰되지 않았다. 직접 읽었을 때 새 세션군은 초심자에게 필요한 개념 구분과 실행
흐름을 유지하면서 체크리스트와 버전별 부가 설명을 덜어 더 집중된 글이었다. 현재
포크군은 더 풍부했지만 기존 보고서와 직전 대화의 구조를 반복해 새 보고서라기보다
이전 설명을 확장한 인상이 강했다.

후보의 계보를 가린 독립 판독에서도 새 세션군이 개념 흐름, 범위 억제, 가독성,
독립적 구성에서 우세하다고 평가됐다. 반면 사실성과 출처 규율은 현재 포크군이
근소하게 나았다. 새 세션군에는 릴리스와 revision을 혼동한 문장, `helm lint`의
성공과 실패를 뒤바꾼 문장, `--wait-for-jobs` 경계를 생략한 도식이 있었다. 새
세션은 문맥 오염을 줄였지만, 사실성 검증을 대신하지는 않았다.

## 판단과 한계

이 한 쌍은 통계적 우월성을 증명하지 않는다. 다만 다음 인과 경로는 명확히
관찰됐다.

1. 이전 보고서 검토 대화가 최신 일반 세션에 남았다.
2. 현재 보고서 계획이 그 세션을 포크했다.
3. 직전 대화의 표현과 관점이 계획의 필수 항목으로 승격됐다.
4. 최종 보고서가 그 관점과 구조를 다시 사용했다.

따라서 새 보고서의 최초 계획을 새 제공자 세션에서 시작하는 방향은 제품 반영
후보로 삼을 근거가 충분하다. 구현 시에는 최초 계획만 새 세션에서 시작하고,
계획 이후의 보고서 단계는 그 새 계획 세션을 이어 가야 한다. 기존 보고서 수정과
이어쓰기는 해당 보고서 세션을 계속 사용해야 하며, 일반 대화 기억이나 검색 경계를
함께 초기화해서는 안 된다.

다음 단계는 이 최소 경계를 제품 코드에 반영한 뒤, 일반 계획형과 장문 보고서의
세션 계보 테스트 및 명시적 보고서 수정 회귀 테스트를 실행하는 것이다.
